# 学生选课匹配助手 · 比赛提交 / Student Course Matching Assistant

CityUHK 本科生 GE 选课辅助工具的**前端可交互原型**，中英双语。纯静态（HTML/CSS/JS），无后端、无网络请求、不接任何 API。

> 数据全部为**合成示例**，不代表真实课程资料，不得作为选课依据。
> All data is synthetic sample data, not real course information.

---

## 一、怎么运行

双击 `01-页面与界面/index.html` 即可，无需构建、无需服务器、无需联网。

| 链接 | 效果 |
|---|---|
| `index.html` | 中文界面，从第一步开始 |
| `index.html?lang=en` | 英文界面 |
| `index.html?stage=3` | 直接看候选课程结果（跳过前两步） |
| `index.html?stage=4&pick=3` | 核实清单 + 周课表，自动勾选 3 门 |

页面右上角可随时切换中文 / EN，已勾选的清单不会丢。

`06-截图/` 里是中英两套四步截图（`zh-step1~4.png`、`en-step1~4.png`），可直接用于 PPT。

## 二、目录结构（按类别）

```
比赛/
├── 00-项目说明.md          ← 本文件
├── 01-页面与界面/          界面层：页面结构、样式、交互渲染
│   ├── index.html          入口页面（双击这个）
│   ├── app.js              渲染与交互（不含业务判断）
│   ├── styles.css          暖白纸感主题 + 响应式断点
│   └── i18n.css            语言切换控件 + 英文排版微调
├── 02-核心逻辑/            判定层：与界面、语言都无关的纯函数
│   └── logic.js            整班冲突、三态判定、安排影响、组合复核
├── 03-示例数据/            数据层：接真实数据只改这里
│   └── data.js             12 门 GE 课程 + 4 门已选课程（字段带 zh/en）
├── 04-文案字典/            文案层：所有界面文字的唯一定义处
│   └── i18n.js             中英两套字典 + 取值/占位符工具
├── 05-测试与校验/          质量保障：规则测试 + 浏览器交互测试 + 布局体检
│   ├── logic.test.js       规则与双语文案回归（28 项，不需要浏览器）
│   ├── ui.test.js          真实浏览器交互回归（75 项，中英各一遍）
│   └── diag.js             布局体检：溢出/裁切测量（3 档宽度 × 2 语言）
└── 06-截图/                中英两套四步截图
```

**分层原则**：判定只在 `02-核心逻辑`，文案只在 `04-文案字典`，`01-页面与界面/app.js` 不做业务判断。这样改规则、改界面、改文案互不影响，规则与文案也都能被测试覆盖。

依赖顺序（`index.html` 底部已配好）：文案 → 数据 → 逻辑 → 界面。

## 三、产品做了什么（对应方案文档的验收点）

流程：**确认课表 → 剩余要求与偏好 → 候选课程 → 去官方核实**

- **步骤一 确认课表**：读入已选课程并逐条显示课程代码/班别/星期/时间，可修改、删除、手动补充；每门可标「识别待确认」；确认后锁定，锁定后只读。
- **步骤二 剩余要求**：目标 GE 范畴、拟增加学分与上限、已修课程代码、不可用时段、排序偏好、课间缓冲；以及「只显示已知条件符合」开关。
- **步骤三 候选课程**
  - 每行 = 把这一门**单独**加进已锁课表的结果：课程/班别、完整上课时间、时间匹配、需求对应、安排影响（到校天数、课间空档）、资格状态。
  - **三态标签**：已知条件符合 / 仍有条件待核实 / 明确不符合，没有含糊的「可选」。
  - **整班匹配**：Lecture 可行但 Tutorial 撞堂时整门判为不可用；多个可行班别可在详情里切换（只换推荐，不会自动加入清单）。
  - **排除列表**可展开，写明撞哪门课、哪个班别、哪个时段。
  - **组合复核**：勾选 ≥2 门后重新两两检查，给出组合后到校天数，并提示「组合可行 ≠ 都能选上」。
  - **空结果**分三类原因（时间冲突 / 范围过窄 / 被开关隐藏），不会是空白页。
  - 每行可展开「为什么推荐 · 待确认项 · 数据来源」，含来源名称、核对日期、官方入口链接。
- **步骤四 官方核实**：周课表预览（已锁定 vs 本次勾选）、逐门 3 项人工核实勾选框、复制清单、明确声明不查余位 / 不抢课 / 不代提交。

**明确不做**：抢课、代替学校审核培养方案、跨校适配、给课程贴「水课/高分」标签、承诺选上、实时余位监控、索取学号密码。

## 四、怎么跑测试

```powershell
# 1) 规则 + 双语文案测试（不需要浏览器）
node 05-测试与校验/logic.test.js

# 2) 交互测试 + 布局体检（先开一个带调试端口的 Chrome）
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --headless=new --disable-gpu --remote-debugging-port=9222 --remote-allow-origins=* `
  --user-data-dir="$env:TEMP\cm-prof" "about:blank"

node 05-测试与校验/ui.test.js           # 中英各跑一遍完整流程
node 05-测试与校验/diag.js zh 1 2 3 4  # 中文布局体检
node 05-测试与校验/diag.js en 1 2 3 4  # 英文布局体检（英文更长，单独测）
```

结果：规则 28/28、交互 75/75 通过；中英两套界面在 1360 / 820 / 390 三档宽度下均无横向溢出与内容裁切；英文界面正文无漏翻中文（有自动断言）。

## 五、接真实数据时改哪里

只改 `03-示例数据/data.js`，其余不用动。单门课的数据契约：

```js
{
  code: 'GE2318',
  title: { zh: '课程名', en: 'Course title' },   // 双语；只有一种语言就两边填一样
  area: 'area3',                                 // 语言无关的键：english|area1|area2|area3|china
                                                 // 拿不到类别填 null → 自动标「待核实」
  credits: 3,
  desc: { zh: '…', en: '…' },
  source: {
    name: { zh: '来源名', en: 'Source name' },
    url: 'https://...',                          // 官方资料入口
    retrievedAt: '2026-11-10'                    // 核对日期（界面会显示）
  },
  conditions: {
    prereq: null,                                // 填字符串 = 需先修 → 标「待核实」
    exclusions: [],                              // 与已修课程互斥的代码
    majorRestricted: false,                      // true = 限主修 → 标「待核实」
    note: { zh: '', en: '' }
  },
  sections: [                                    // 每个班别
    { id: 'L1', component: 'Lecture', days: ['Mon'], start: '09:00', end: '10:50',
      dateRange: ['2027-01-11', '2027-04-24'] }  // 支持半学期
  ],
  bundles: [                                     // 必须整班一起选的组合
    { id: 'L1+T1', label: 'L1 (Lecture) + T1 (Tutorial)', sections: ['L1', 'T1'] }
  ]
}
```

**字段缺失是允许的**：缺班别时间、缺 GE 类别、缺日期范围都会自动落到「待核实」，不会当成「符合」。这是刻意设计，接数据时不要为了「看起来完整」填默认值。

改文案只动 `04-文案字典/i18n.js`；英文键漏了会回落成中文，测试里有一条专门断言「英文界面不得出现中文」。

本项目**不做数据抓取**（不接 API、不写爬虫），数据由数据负责人以 CSV/JSON 提供后再转成上面的结构。

## 六、演示用的反例（都在示例数据里，可直接讲）

| 反例 | 哪门课 | 演示点 |
|---|---|---|
| Lecture 可行但 Tutorial 撞堂 | GE1401 | 整班匹配：只有 L1+T1 可行，L1+T2 撞 CS2334；还能切到 L1+T3 |
| 唯一 Tutorial 撞堂 → 整门排除 | GE2504 | 排除列表写明「周二 11:00-11:50 与 CS2334 重叠」 |
| 类别不在范围内 | 选「中国文明」时 | 明确不符合 |
| 先修条件 | GE2301 | 待核实（不替你判断） |
| 主修限制 | GE2201 | 待核实 |
| 班别时间未公布 | GE2601 | 资料不足 → 待核实 |
| 缺 GE 类别 | GE2901 | 不静默丢弃，仍作为待确认候选出现 |
| 半学期日期范围 | GE2701（后半）vs GE2750（前半） | 同一时段，后半撞 CB2601、前半不撞 |
| 缓冲不足 | GE2410，缓冲调到 20 分钟 | 从「可行」转为「待核实」并说明原因 |
| 组合冲突 | 同时勾 GE1401 + GE2301 | 组合复核检出 2 处冲突并写明时段 |
| 空结果 | 只留一个类别 + 勾「只看已知符合」 | 分类原因，不是空白页 |

## 七、已知限制

- 课表导入是**模拟**的（直接读示例数据）；真实导入解析不在本原型范围。
- 半学期日期范围在步骤一只能查看、不能再改。
- 刷新页面即重置业务状态（避免演示时被上一次操作干扰），只有语言选择会记住。
- 排序是「到校天数 / 课间空档 / 优先补未修类别」三种简化启发式，不是优化目标。
- 英文文案为直译，正式提交前建议再由人润色一遍术语（`04-文案字典/i18n.js` 的 `en` 段）。
- **改文件请用支持 UTF-8 的编辑器**，不要用 PowerShell 的 `Get-Content`/`Set-Content` 往返改写含中文的文件（会变乱码）。
